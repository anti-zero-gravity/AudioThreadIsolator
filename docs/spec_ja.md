# Audio Thread Isolator (ATI) v2.0.0 - 仕様書・ユーザー説明書 (spec_ja.md)

## 1. アプリケーション概要

- **名称**: 再生スレッドアイソレーター / Audio Thread Isolator (略称: ATI)
- **種別**: Windows 常駐ユーティリティ
- **目的**:
  オーディオ再生やマルチメディアアプリの実行中プロセスから、オーディオ再生スレッドを自動特定し、指定したオーディオ用CPUコアへ隔離します。同時にそれ以外を指定した複数の除外コアへ退避させます。高負荷スレッドがオーディオスレッドと同じコアを使わなくすることで、実行待ちキューに登録されてから実行されるまでの待機時間をなくし、スレッド処理タイミングのマイクロジッターやスタッターを極小化します。
- **全監視プロセスへの省電力スロットリング（EcoQoS）自動解除**:
  監視対象として登録されたすべてのプロセスについて、Windows の省電力スロットリング（EcoQoS / 効率モード）を解除するため、PID 検出時に HighQoS を 1 回発行します。これにより、Windows による強制的な実行速度制限やタイマー間引き（15.625ms へのタイマー合流）が解除され、高精度タイマー（1ms）を維持します。

## 2. 画面構成と操作方法

### 2.1 メイン画面 (Main Window)
- **概要**: 登録プロセスの監視状態の確認と、クイック操作（除外、一時停止、優先度変更）を行うメイン画面です。解像度や拡大縮小（スケーリング）変更時も自動的に最適なサイズで表示されます。

#### 操作ボタン構成（右側パネル）
- **`Always on Top`**: メインウィンドウを常に最前面に表示します。
- **`[Edit]`**: 選択プロセスの個別設定ダイアログ（2.5節）を開きます（プロセステーブルの Col 1 / 6 / 7 / 8 / 9 のクリックでも同様）。
- **`[Add]`**: プロセス選択ダイアログ（2.2節）を開きます。
- **`[Remove]`**: 選択したプロセスを監視リストから削除します。
- **`[Settings]`**: 全体設定ダイアログ（2.4節）を開きます。
- **`[Exit]`**: アプリケーションを終了します。
- **列幅・ウィンドウ縦幅のドラッグ調整**: テーブル見出し境界のドラッグによる各列幅の変更、およびメインウィンドウ上下端のドラッグによる縦幅変更は `ATI.ini` に自動保存されます。

- **Voicemeeter 専用マルチ行展開**:
  - Voicemeeter 全エディション（`AppType: 5`、2行）では、ネットワーク送受信とメインオーディオエンジンの各スレッドを専用行へ自動展開して表示・隔離します。
  - **10秒カウントダウン探索と `sleeping...` 移行**:
    - 未確定スロットに対して 10 秒間継続して探索を実行し、未確定行には `Standby 10` 〜 `Standby 1` のカウントダウンが表示されます。
    - 10秒以内に未検出だったスロット（例: Voicemeeter で VBAN 未使用時など）は `sleeping...` へ移行します。休眠行（Col 0 または Col 5）をクリックすると、確定済みスレッドを維持したまま 10 秒カウントダウン探索が再開されます。
  - いずれの行から `[Edit]` またはセルクリックで個別設定を開いて保存した場合も、同一プロセスの全展開行の設定が一括更新されます。
- **Roon 専用常時待機動作 (`AppType: 4`)**:
  - `RoonAppliance.exe` および `RAATServer.exe` はそれぞれ単一行（1スロット）として動作します。
  - 再生停止や無音時にも `sleeping...` へ移行せず、Chromium（`AppType: 2`）と同様に `Searching...` のまま常時待機し、再生再開を即座に捕捉します。

- **2D Priority Matrix Picker（立体優先度ピッカー）**:
  - **`Process Priority`（Col 3）クリック時（プロセス優先度・行選択モード）**:
    - 左ペイン（立体マトリクス）のホバーでは **行（プロセス優先度クラス）のみ** を選択でき、列（スレッド優先度）は変更されません（非管理者起動時は `Realtime` 行は選択できません）。
    - マウスホイール回転でプロセス優先度クラス（行）を上下に 1 段階ずつ切り替えられます。
    - 左ペインの柱（バー）のクリック、ホイール回転後の右ペインクリック、または `Enter` キーで確定・即時反映します（Col 2 に `Fixed` 優先度が設定されているスロットには変更直後に固定優先度を自動再適用）。
    - **非アタッチ状態（淡緑背景）への復帰**: ピッカー内の柱（バー）の外側をクリック、またはホイールを回さずに右ペインをクリックすると、`Thread Priority`（Col 2）と `Process Priority`（Col 3）の両方が初期の優先度非アタッチ状態（淡い緑色背景）へ戻ります。`Esc` キーまたはピッカー外クリックでキャンセルします。
  - **`Thread Priority`（Col 2）クリック時（スレッド優先度モード）**:
    - **通常ホバー（`Ctrl` なし）**: 現在のプロセス優先度クラスの**行に固定されたまま**、横方向の 7 段階相対優先度（`Idle (-15)` 〜 `Time Critical (+15)`）のみを選択します（カーソルが上下の行へ外れても行は切り替わりません）。
    - **`Ctrl` キー押下＋左ペインホバー（2D 選択）**: 左ペインの立体マトリクス上で **`Ctrl` キーを押している間のみ行から外れて 2 次元選択が可能**になり、プロセス優先度クラス（Col 3・行）とスレッド優先度（Col 2・列）を同時に選んで一括適用できます（右ペインへカーソルを移動した際は選択中の行状態が保持されます）。
    - **右ペインの数値・マウスホイール操作**: マウスホイールを回転すると、右ペインの実効優先度の数値が **`1〜31`（非管理者起動時は `1〜15`）の範囲で 1 ずつ増減**します。現在のプロセス優先度行の 7 段階相対優先度と一致する数値はその相対優先度として、7 段階にない中間値（例: `Normal` 時の `11〜14` など）は **`Fixed <数値>`** として直接指定できます（左ペインのバーに再ホバーするとバー選択へ戻ります）。
    - **確定・非アタッチ復帰・キャンセル**: 左ペインの柱（バー）クリック、ホイール回転後の右ペイン（数値パネル）クリック、または `Enter` キーで確定・即時反映します。柱（バー）の外側をクリック、またはホイールを回さずに右ペインをクリックすると、`Thread Priority` と `Process Priority` の両方が初期の非アタッチ状態（淡い緑色背景）へ戻ります。`Esc` キーまたはピッカー外クリックでキャンセルします。
  - **`Normal` 優先度クラス表示**: `Normal` 選択・ホバー時は、Windows が前面（Foreground）時と背面（Background）時で実効優先度を動的に切り替える仕様に合わせて上下 2 行が同時発光し、右ペインに FG / BG 両方の実効優先度および動作説明が表示されます。
  - 2Dピッカーで優先度を決定するとセル背景色の緑が白に変わり、優先度の変更が開始します。優先度の監視を止めたいときは、2Dピッカーで優先度の外か右ペインをクリックしてください。各登録アプリ起動時の優先度復旧はおこないませんが、各登録アプリを再起動すれば本来の優先度から変更されないことが確認できます。

- **下部凡例バーの先頭カウント表示**:

#### 優先度設定と Windows 基本優先度 (Base Priority)

標準プロセス優先度クラス（Normal）において、各スレッド優先度が対応する Windows の基本優先度（1〜15）は以下の通りです。

| ATI 設定値 | Base Priority | 動作特性 |
|:---|:---:|:---|
| **`Idle (-15)`** | **1** | CPU の空き時間のみで動作（極小負荷・低ジッター）。 |
| **`Lowest (-2)`** | **6** | 通常スレッドより低い優先度。同居スレッド検知（Half-Isolated）自動昇格時の基準値。 |
| **`Below Normal (-1)`** | **7** | 通常スレッドよりやや低い優先度。 |
| **`Normal (0)`** | **8** | OS の標準スレッドと同等の優先度。 |
| **`Above Normal (+1)`** | **9** | 通常スレッドより一段高い優先度。 |
| **`Highest (+2)`** | **10** | 通常スレッドより優先して実行。 |
| **`Time Critical (+15)`** | **15** | 通常アプリケーションにおける最高位優先度。 |

- **Realtime 優先度 (実効優先度 16〜31)**:
  - `Realtime` 優先度クラスおよび実効優先度 `16〜31`（ホイールによる数値指定を含む）は、ATI を管理者権限で起動している時のみピッカー上で選択可能です（非管理者起動時は `Realtime` 行および `16` 以上の数値は選択できません）。

### 2.2 プロセス選択ダイアログ (Process Picker Dialog)
- メイン画面の `[Add]` から起動します。実行中のプロセス行をクリックして追加対象のチェックを切り替え、`[Done]` で監視リストへ追加します（コアマスクの初期値は全体デフォルト設定が適用され、優先度は未アタッチの淡緑表示で開始します）。`[Refresh]` で実行中プロセス一覧を再取得、`[Cancel]` で追加せず閉じます。
- 先頭の赤い **`!` カラム** をクリックしてチェックを入れたプロセスは `UnlistedExclusions` として登録され、リスト外（非監視）の全プロセスを一括マスクする際の対象から個別に除外されます（`!` カラムにホバー中のみ下部に説明文が表示されます）。

### 2.3 システムトレイ（タスクバー通知領域）動作
- ウィンドウ右上の「×」ボタン、または最小化でタスクバー通知領域（システムトレイ）に収納されます。
- **左クリック**: メインウィンドウを最前面に復帰表示します。
- **右クリックメニュー**:
  - **`Open Settings`**: メインウィンドウを表示します。
  - **`Start with Windows`**: Windows 起動時の自動スタートアップ常駐の有効/無効を切り替えます。
  - **`Restart`**: アプリケーションを通常再起動します。
  - **`Restart as Administrator`**: 管理者権限（UAC 昇格）で再起動します（既に管理者権限で動作中は自動非表示）。
  - **`Exit`**: アプリケーションを終了します。

### 2.4 全体設定ダイアログ (Global Settings Dialog)
メイン画面の `[Settings]` から開きます。新規登録プロセスのデフォルト値設定と、システム全体の一般プロセスに対する専用コア保護マスクを管理します。

| 項目名 | 概要・役割 | 操作仕様 |
|:---|:---|:---|
| **コア設定表** | 新規登録時に適用するデフォルトのオーディオ専用コア（行 0: `Audio Core`）および除外コア（行 1: `Excluded`）を設定（同一コアの重複防止および最低 1 コア保護が自動で動作）。 | セルクリックでトグル選択（表上のマウスホイールで横スクロール） |
| **`Default Audio Core (Mask)`** / **`Excluded (Mask)`** | デフォルトのオーディオ専用コアおよび除外コアをビットマスク（またはカンマ区切りコア番号）で指定。 | 直接入力または表操作 |
| **`Apply` (Audio Core 行)** | **【専用コア保護（排他チェック）】** ATI 登録プロセス（および `UnlistedExclusions`）以外の全一般プロセスに対し、「オーディオ専用コアを使わないアフィニティマスク」を一括適用し、以降の新規起動プロセスへも `INI×10` 周期で自動追従適用します。 | チェックで有効化（下段と排他連動）・OFFでポーリング停止 |
| **`Apply` (Excluded 行)** | **【除外マスク適用（排他チェック）】** ATI 登録プロセス（および `UnlistedExclusions`）以外の全一般プロセスに対し、除外コアマスクの内容を一括適用し、以降の新規起動プロセスへも `INI×10` 周期で自動追従適用します。 | チェックで有効化（上段と排他連動）・OFFでポーリング停止 |
| **`Polling Interval (ms)`** | 監視スレッドの巡回周期（`100` / `200` / `500` / `1000` ms）。基本的に500msから変更しないで下さい。 | 数値入力（有効値へ自動補正） |
| **`Unmask All`** | 両方の `Apply` チェックが OFF かつマスク適用済みの時のみ緑（アクティブ）になり、監視中プロセスを除く全プロセスの保護マスクを明示的に一括解除して全コアの OS 標準状態へ復元します。 | クリックで解除 |
| **`OK` / `Cancel`** | 設定を保存（OK）または破棄（Cancel）して閉じます。 | クリック |

### 2.5 個別設定ダイアログ (Thread Isolation Settings Dialog)
メイン画面でプロセステーブルの対象セル（Col 1 / 6 / 7 / 8 / 9）をクリック、または `[Edit]` ボタンで開きます。全体設定（2.4節）と同じコア設定表（セルクリックで ON/OFF トグル、表上のマウスホイールで横スクロール）・マスク入力欄・スレッド優先度ドロップダウンを用いて、選択中のプロセス（`Target Process`）固有の割り当てを編集し、`OK` で `ATI.ini` へ保存します（`Audio Core` にはカンマ区切り `1, 2` 等による複数コア指定も可能）。

## 3. アプリケーション種別ごとの自動判定仕様

- **Chromium 系ブラウザ (Chrome, Edge, Brave, Vivaldi 等)**:
  ブラウザ全体のプロセス群から内部の専用音声サービスプロセス（Audio Service）を自動特定し、短時間で入れ替わるスレッドの中から音声送出スレッドを追従・隔離します。
- **一般的なオーディオ・動画再生アプリ (foobar2000, mpv, Firefox 等)**:
  スレッドの CPU 負荷動向や音声関連処理の特徴から再生スレッドを特定し、音声再生が止まった無音待機状態では自動的に休眠（`sleeping...`）へ移行します。
- **Voicemeeter シリーズ (`AppType: 5`)**:
  無印（`voicemeeter` / `voicemeeter_x64`）、Banana（`voicemeeterpro` / `voicemeeterpro_x64`）、Potato（`voicemeeter8` / `voicemeeter8_x64`）の全エディションを自動認識し、登録時に **2行展開** となります。
  - 1行目（親行）: `VBAN - <プロセス名>`（ネットワーク音声送受信スレッド）
  - 2行目（`└`）: `VAIO/AUX & DSP -`（物理Hardware OUT・仮想I/O・ミキシング・DSP処理を一括担当するメインエンジンスレッド）
  - **スロット別 INI 2行独立フォーマット**: `ATI.ini` では `<プロセス名>(1)=...`, `<プロセス名>(2)=...` の 2 行構成で保存・復元され、各スロットの `AudioCore`（単一コア番号または `0xC0C` 等の16進マスク）、`AudioPriority`、`Bypass:1` を独立して保持します。手編集ミス等で 2 行のうち 1 行でも欠けていた場合は起動時に無視され、終了時に欠けていた場合は 2 行丸ごと `ATI.ini` からクリアされます。
  - **スロット個別 Bypass（マスクスイッチ）**: メイン画面の 2 行それぞれの `!` カラム（Col 0）または `PID / TID` カラム（Col 5）をクリックすると、そのスロット単体で Bypass ON / OFF を切り替えられます。Bypass ON 時にはスレッド優先度はそのまま維持しつつ、除外マスク（`NormalCores`）が即時適用されます（Bypass OFF で再び専用オーディオコアマスクへ即時復帰）。
  - 個別設定ダイアログでは、クリック（または `[Edit]` 選択）した行のスロットが編集対象となり、`Audio Core` 行で単一コアまたは複数コアをトグル選択・16進マスク入力できます。
- **Windows オーディオエンジン (`audiodg.exe`)**:
  Windows 標準のオーディオグラフ分離プロセス `audiodg.exe`（`AppType:0` 固定）では、内部スレッドが短時間で次々と入れ替わるため単一 TID の特定は行わず、**`audiodg.exe` のプロセス全体（PID）にオーディオ用コアマスク・プロセス優先度クラス・HighQoS（PID 検出時の初回 1 回）を適用し、配下の全スレッド（全 TID）へ指定のスレッド優先度を適用**します（Col 5 表記は `PID <pid> / -`、Col 2 の実効優先度には待機スレッドではなく稼働中の音声本体スレッドの値を表示し、初回 PID 確定時はスレッド数に関わらず `Chgs` を `+1`）。以降はポーリングごとに新規生成された TID を検出し次第スレッド優先度を適用して `Chgs` を `+1` 増加させます。監視リストからの削除時・Bypass 移行時・ATI 終了時には、PID を全コアおよび `Normal` 優先度クラスへ戻し、全 TID に `+2`（`Highest`）を適用して標準状態へ復元します。
- **Roon 専用制御 (`AppType: 4` — `RoonAppliance.exe` / `RAATServer.exe` / `RoonBridge.exe`)**:
  - **サーバー PC（Roon Server / Core 側）**: 常駐させた ATI に `RoonAppliance.exe` を登録します。
  - **レンダラー PC（Endpoint / Roon Bridge 側）**: 常駐させた ATI に `RAATServer.exe` を登録します（`RoonBridge.exe` を登録した場合は自動で `RAATServer.exe` へフォールバックします）。
- **定常状態における 3 秒周期監視 (`AppType: 1, 3, 4, 5`)**:
  短時間でスレッドが入れ替わる `audiodg.exe`（`AppType: 0`）および Chromium（`AppType: 2`）を除き、オーディオスレッドの隔離が確定して定常状態に入ったプロセス（ならびに `RAATServer.exe` の待機中）は、プロセス終了検知のみ通常の巡回周期で維持しつつ、スレッド列挙および優先度・アフィニティ維持確認を約 3 秒に 1 回の低頻度サイクルへ自動的に切り替え、監視オーバーヘッドを抑えます（UI からの優先度・コア変更や再検索操作時は即座に反映されます）。

### 4.2 プロセス別設定セクション `[Processes]`

登録されたプロセスごとに、実行ファイル名をキーとして以下のパラメータをカンマ区切り形式で保存します。

| パラメータ名 | 設定内容・意味 | 有効値 |
|:---|:---|:---|
| **`AudioCore`** | オーディオスレッドを固定する専用コア番号または16進マスク。複数指定時はカンマ区切り（例: `AudioCore:11, 3, 0xC00`）。 | `0` 〜 (最大コア数 - 1)、16進マスク（`0x`〜）、複数カンマ区切り |
| **`AudioPriority`** | オーディオスレッドに適用する優先度（相対7段階または `F` 付きの固定優先度）。複数スロット時はカンマ区切り（例: `AudioPriority:-15, F19`）。 | `-15`, `-2`, `-1`, `0`, `1`, `2`, `15`、または `F1` 〜 `F31`、複数カンマ区切り |
| **`ProcessPriority`** | ピッカー操作により明示指定されたプロセス優先度クラス（未操作時は出力されず、実プロセスの優先度を維持）。 | `Idle`, `Below Normal`, `Normal`, `Above Normal`, `High`, `Realtime` |
| **`NormalCores`** | 通常スレッド群を割り当てる退避コアマスク（16進数）。複数コアが含まれる場合、アフィニティマスクは複数コアを維持したまま、通常スレッドの `Cycles Delta` 降順（負荷順）で対象コアへ Ideal CPU をラウンドロビン自動分散します。 | `0x` で始まる16進数マスク |
| **`Bypass`** | 一時除外状態（1: 除外中、未指定: 監視有効）。 | `1` |
| **`AppType`** | アプリ種別判定モード（0: `audiodg.exe` 専用、1: 一般オーディオ、2: Chromium、3: DAW型高負荷、4: Roon 専用、5: Voicemeeter 専用）。 | `0`, `1`, `2`, `3`, `4`, `5` |

## 5. 制約事項・注意事項

1. **一時停止（`❚❚`）機能の取り扱い**:
   - 本機能は「一時的に音声を停止させ、対象スレッドが音声再生を行っている実際のスレッドであるかを確認する」ための検証機能です。ミュート代わりに使用するとアプリ全体のデッドロックやクラッシュを引き起こす恐れがあるため、検証目的以外での使用は避けてください。
2. **一時除外（`!` / Bypass）時の挙動**:
   - チェックを入れて Bypass に移行すると、ATI による該当プロセスの監視・調整は停止します。直前までに適用されていたスレッドのアフィニティや優先度は維持され、即座に OS 標準状態に戻るわけではありません（※例外として `audiodg.exe` は、Bypass 時・監視削除時・アプリ終了時に標準状態へ自動復元されます）。
3. **多重起動防止と自己保護**:
   - 多重起動は行わず、既に起動している状態で再度起動された場合は、起動中の ATI のタスクトレイアイコンを復旧させ、メインウィンドウを前面にアクティブ化して後発プロセスは即座に終了します（Explorer の不正終了等でタスクトレイからアイコンが消失した場合の復旧措置も兼ねています）。また、ATI 自身の監視処理がオーディオ専用コアを圧迫しないよう、ATI 自身を自動的に通常コア群へ退避させて動作します。
4. **起動モード（通常起動 / 管理者権限起動）による制御範囲の違い**:
   - タスクトレイメニューの「`Restart as Administrator`」等から管理者権限で起動すると、リアルタイム優先度（Base 16〜31）が選択可能になるほか、制御できるプロセスの範囲が広がります。
   - **Unlisted マスク適用対象の拡大**: 通常起動では権限の制約によりスキップされるシステムサービスや昇格プロセスに対してもアフィニティマスクを適用できるようになります。
   - **`sleeping...` 遷移の低減**: 権限不足が原因でスレッド情報を読み取れずに `sleeping...` へ移行してしまうプロセス（`audiodg.exe` や管理者権限で動作するゲーム・アプリ等）でも、捕捉とコア隔離が可能になります。
5. **マスクを掛けられないプロセス（Windows 保護プロセス）**:
   Windows カーネルの保護機構（PPL: Protected Process Light 等）により、管理者権限であっても外部からのアフィニティ変更が拒絶される以下のシステムプロセス群は自動的にスキップされます。
   - **カーネル・仮想メモリ管理**: `System` (PID 4), `Registry`, `Secure System`, `Memory Compression`
   - **コアサブシステム**: `smss.exe`, `csrss.exe`, `wininit.exe`, `winlogon.exe`
   - **セキュリティ・認証サブシステム**: `lsass.exe`, `services.exe`, `SecurityHealthService.exe`
   - **マルウェア対策**: `MsMpEng.exe` (Microsoft Defender), `NisSrv.exe`
   - **グラフィックス・フォント・ドライバ分離ホスト**: `dwm.exe`, `fontdrvhost.exe`, `WUDFHost.exe`
   - **システム保護 `svchost.exe` 群**: セキュリティ・システムイベント等をホストする保護インスタンス群 (RPCSS, DcomLaunch, BrokerInfrastructure 等)
6. **通常スレッドの Ideal CPU 自動分散（ラウンドロビン）の適用範囲と動作契機**:
   `NormalCores` に複数コアが割り当てられている場合、アフィニティマスクは複数コアを維持したまま、直近の CPU 負荷（`Cycles Delta` 降順）に応じて対象コアへ Ideal CPU（優先コア）をラウンドロビン自動分散します。
   - **Affinity Mask と Ideal CPU の違い**:
     - **Affinity Mask（ハード制約）**: スレッドの実行が許可される CPU コアの集合（境界線）。マスク外のコアでは物理的に動作できません。
     - **Ideal CPU（優先ヒント）**: 許可されたコア群の中で、OS スケジューラが優先してスレッドを割り当てる推奨コア（1個）。
   - **分散の動作例**:
     退避先（`NormalCores`）として `#0`〜`#3` コア（4コア）を指定した場合、全通常スレッドのアフィニティマスクは `#0`〜`#3` に共通設定された上で、CPU 負荷が最も高いスレッドから順に Ideal コアが `#0 ➔ #1 ➔ #2 ➔ #3 ➔ #0 ➔ #1...` と循環指定されます。これにより、1 つのコアに高負荷スレッドが集中するのを防ぎます。
   - **適用対象**: 一般オーディオアプリ（`AppType: 1`）、DAW型（`AppType: 3`）、Roon（`AppType: 4`）、Voicemeeter（`AppType: 5`）などの通常スレッド退避処理を持つ登録プロセス。
   - **適用対象外**:
     - **`audiodg.exe` (`AppType: 0`)**: プロセス全体（全スレッド）が専用オーディオコアへ一括隔離されるため対象外です。
     - **Chromium 系ブラウザ (`AppType: 2`)**: 専用探索パスを持つため一括ソートは行われず、初登場の新スレッドのみが空きコアへ順次配置されます。
     - **未登録（Unlisted）プロセス**: プロセス単位のアフィニティマスク適用のみを行い、スレッド単位の Ideal CPU 制御は行いません。
   - **動作契機（リバランスタイミング）**:
     頻繁なコア移動による CPU キャッシュミスを防ぐため、定常状態では各スレッドの Ideal CPU はそのまま維持されます。「新規スレッドが生成された時」「オーディオスレッドが確定・交代した時」「ユーザーが設定を変更した時」にのみ、最新の負荷順で再ソート・再配置されます（スレッドが消滅しただけでは既存配置を維持）。
7. **時々自動生成されるバックグラウンドプロセス（Unlisted 対象）の正体と退避の意義**:
   ATI のメイン画面凡例にある `Unmonitored Processes Masked` のカウントは、PC を操作していなくても時間経過とともに徐々に増加します。これは Windows OS や常駐アプリが定期的に短命なプロセスを自動生成しているためです。
   - **生成されるプロセスの正体と目的**:
     - **Windows 診断・保守タスク**: `CompatTelRunner.exe`（互換性テレメトリ）、`DeviceCensus.exe`（デバイス構成診断）、`taskhostw.exe`（タスクスケジューラ汎用ホスト）など、OS の自己診断や保守のために短時間起動します。
     - **自動アップデータ**: `GoogleUpdate.exe`, `MicrosoftEdgeUpdate.exe`, `MpCmdRun.exe`（Microsoft Defender 定義更新）など、セキュリティや最新版確認のために数分〜数時間間隔で間欠起動します。
     - **ツール・開発環境のサブプロセス**: コマンド実行や拡張機能のバックグラウンド処理に伴う `conhost.exe` や一時ワーカープロセス。
   - **退避の意義（なぜマスクが必要か）**:
     Windows の標準仕様では、新規起動したプロセスは「オーディオ専用コアを含む全コア」で動作可能として生成されます。これらを放置すると、突発的に起動した診断プロセス等がオーディオ専用コア上で CPU 時間を消費し、音切れ（ジッター・グリッチ）の原因となります。ATI はこれらを検出して速やかに通常コア群へ自動退避させます。
   - **ソフトな退避（異音防止機構）**:
     新プロセスの退避処理がオーディオ再生に干渉しないよう、既に退避マスクを継承済みのプロセスに対する重複設定の抑止と、複数プロセス検出時の時間分散適用によるソフトな退避を行っています。
