# Audio Thread Isolator (ATI) v1.0.5 - 仕様書・ユーザー説明書 (spec_ja.md)

## 1. アプリケーション概要

- **名称**: 再生スレッドアイソレーター / Audio Thread Isolator (略称: ATI)
- **種別**: Windows 常駐ユーティリティ
- **目的**:
  オーディオ再生やマルチメディアアプリの実行中プロセスから、オーディオ再生スレッドを自動特定し、指定したオーディオ用CPUコアへ隔離します。同時にそれ以外を指定した複数の除外コアへ退避させます。高負荷スレッドがオーディオスレッドと同じコアを使わなくすることで、実行待ちキューに登録されてから実行されるまでの待機時間をなくし、スレッド処理タイミングのマイクロジッターを極小化します。
- **全監視プロセスへの省電力スロットリング（EcoQoS）自動解除**:
  監視対象として登録されたすべてのプロセスについて、検出・稼働時に自動的に Windows の省電力スロットリング（EcoQoS）を解除し、HighQoS（最高実行速度および高精度タイマー保持）を適用します。これにより配下の全スレッドがフルクロックで駆動され、省電力制御による音途切れや遅延を防止します。

## 2. 画面構成と操作方法

### 2.1 メイン画面 (Main Window)
- **概要**: 登録プロセスの監視状態の確認と、クイック操作（除外、一時停止、優先度変更）を行うメイン画面です。解像度や拡大縮小（スケーリング）変更時も自動的に最適なサイズで表示されます。

#### 操作ボタン構成（右側パネル）
- **`Always on Top`**: メインウィンドウを常に最前面に表示します。
- **`[Edit]`**: 選択プロセスの個別設定ダイアログ（2.5節）を開きます（行ダブルクリックでも同様）。
- **`[Add]`**: プロセス選択ダイアログ（2.2節）を開きます。
- **`[Remove]`**: 選択したプロセスを監視リストから削除します。
- **`[Settings]`**: 全体設定ダイアログ（2.4節）を開きます。
- **`[Exit]`**: アプリケーションを終了します。

#### プロセステーブル (監視一覧)

| 列 | 見出し | 概要・役割 | 操作仕様 |
|:---:|:---|:---|:---|
| 0 | **`!`** | 監視対象と一時除外（Bypass）の切り替え。チェックを入れると ATI の介入を停止します。| クリックでトグル切り替え |
| 1 | **`Process Name`** | 監視対象として登録されたアプリケーション名（`.exe` は省略表示）。<br>`IgnoreSig:t` による複数スレッド特定時は、2行目以降に「└」ツリー線を表示して親子関係を明示。 | ダブルクリックで個別設定を開く。<br>見出しクリックで昇順ソート（「SORT?」確認あり） |
| 2 | **`Thread Priority`** | オーディオスレッドに適用する相対優先度。<br>複数スレッド展開時は各行ごとに立体優先度ピッカーから個別に優先度を選択可能。 | セルをクリックして立体優先度ピッカーから選択 |
| 3 | **`Process Priority`** | オーディオスレッドを保持するプロセス（PID）に適用する優先度クラス。 | セルをクリックして立体優先度ピッカーから選択 |
| 4 | **`❚❚`** | 検証用の一時停止機能。対象オーディオスレッドを一時停止させて音声を止め、真の再生スレッドであるかを確認します。<br>複数スレッド展開時は各行（TID）ごとに個別に一時停止可能。<br>**（※アプリ停止の恐れがあるためミュート目的での使用は禁止）** | クリックで個別トグル切り替え |
| 5 | **`Audio Core PID/TID`** | オーディオスレッドの検出状態、特定されたプロセスID (PID) およびスレッドID (TID) を表示。 | クリック操作：休眠時は探索リスタート、稼働中は Bypass 切り替え |
| 6 | **`TIDs`** | 監視スレッド数。通常確定時は `1`、探索中および Chromium / `audiodg.exe` ではプロセス内全スレッド数、休眠中は `0` を表示。 | ダブルクリックで個別設定を開く。 |
| 7 | **`Chgs`** | オーディオスレッドを検出し優先度適用された回数。 | ダブルクリックで個別設定を開く。 |
| 8 | **`Audio`** | オーディオ再生スレッドを専有させる CPU コア番号（例: `#1`）。複数スレッド展開時は各行のスレッドに割り当てられたコアを個別表示。 | ダブルクリックで個別設定を開く。 |
| 9 | **`Excluded`** | 通常スレッドの退避先から除外されている CPU コアの一覧（例: `!#1`）。<br>複数スレッド展開時は、親プロセスが同一で退避設定が共通であるため、2行目以降には `same` と表示。 | ダブルクリックで個別設定を開く。 |

- **`IgnoreSig:t` マルチオーディオスレッド展開**:
  - `ATI.ini` 内で `IgnoreSig:2` 等のスレッド数 `t`（自然数）を指定することで、標準シグネチャを持たないアプリ（Voicemeeter 等）を含め、CPU活動量の高い上位 `t` 個のオーディオスレッドを自動特定・隔離し、`t` 行に展開表示します。
  - **10秒カウントダウン探索と同時 `sleeping...` 移行**:
    - 未確定スロットに対して 10 秒間継続して探索を実行し、探索中の行には `Standby 10` 〜 `Standby 1` のカウントダウンが表示されます（後続の未確定行は `Standby 10` で待機）。
    - 10秒以内に次スレッドが検出されなかった場合、未確定スロットはすべて同時に `sleeping...` へ移行します。休眠行（Col 0 または Col 5）をクリックすると、確定済みスレッドを維持したまま 10 秒カウントダウン探索が再開されます。
  - いずれの行から `[Edit]` またはダブルクリックで個別設定を開いて保存した場合も、同一プロセスの全展開行の設定が一括更新されます。

- **2D Priority Matrix Picker（立体優先度ピッカー）による Rank 指定**:
  - `Thread Priority`（Col 2）または `Process Priority`（Col 3）セルをクリックすると、7×7 の立体ビジュアルマトリックスがポップアップ表示されます。
  - マウスホバーで各柱の情報（Base Priority、Rank #、Process Class、Thread Priority）が確認でき、柱をクリック（Rank 1〜49 指定）すると稼働中のプロセス・スレッドへ即時適用されると同時に `ATI.ini` へ保存されます。

#### 状態表示（Col 5）およびインジケーター一覧

| 表示テキスト | インジケーター表示 | 状態の意味 | セルクリック時の挙動 |
|:---|:---|:---|:---|
| `Not running` | なし（未起動チェック `☐` / `☑`） | アプリが起動していない待機状態。 | チェックで起動前の事前 Bypass 設定が可能 |
| `Searching...` | ● コーラルピンク | オーディオスレッドを探索中。 | Bypass 切り替え |
| `Standby` / `Standby 10..1` | ● コーラルピンク | 常時監視スタンバイ状態。音声出力の発生を監視中。 | Bypass へ移行（! 列に ☑ を表示） |
| `sleeping...` | ● 薄紫 / 赤 交互点滅 | 無音・無活動のため監視休眠中。 | 直ちに探索をリスタート |
| `PID <pid> / TID <tid>` | ● 青緑 | オーディオスレッドが特定され、専用コアへ正常に隔離完了（`audiodg.exe` は `PID <pid> / -` 表示）。 | Bypass へ移行（! 列に ☑ を表示） |
| `PID <pid> / Searching...` | ● コーラルピンク | Chromium 音声プロセスを特定し、内部スレッドを探索中。 | Bypass へ移行（! 列に ☑ を表示） |
| (Half-Isolated 発生時) | ● 鈍い黄色 / 青緑 交互点滅 | ドライバ等の仕様でCPUコアが固定され退避できないスレッドがオーディオ専用コアに同居中。オーディオスレッドが `Idle (-15)` の場合は `Lowest (-2)` へ自動昇格し、同居スレッド側を1段階低い優先度へ自動抑制します。 | Bypass へ移行（! 列に ☑ を表示） |

- **下部凡例バーの先頭カウント表示**:
  - 全体設定（2.4節）で未登録（Unlisted）プロセス保護の `Apply` チェックボックスが ON の間のみ、メイン画面下部凡例の先頭に **`● <累計数> Unmonitored Processes Masked`**（起動後にマスクを適用した監視対象外プロセスの累計数）が表示されます（チェック OFF 時は非表示）。

#### 優先度設定と Windows 基本優先度 (Base Priority)

標準プロセス優先度クラス（Normal）において、各スレッド優先度が対応する Windows の基本優先度（1〜15）は以下の通りです。

| ATI 設定値 | Base Priority | 動作特性 |
|:---|:---:|:---|
| **`Idle (-15)`** | **1** | CPU の空き時間のみで動作（極小負荷・低ジッター）。 |
| **`Lowest (-2)`** | **6** | 通常スレッドより低い優先度。同居スレッド検知（Half-Isolated）自動昇格時の基準値。 |
| **`Below Normal (-1)`** | **7** | 通常スレッドよりやや低い優先度。 |
| **`Normal (0)`** | **8** | OS の標準スレッドと同等の優先度。 |
| **`Above Normal (+1)`** | **9** | 通常スレッドより一段高い優先度。 |
| **`Highest (+2)`** | **10** | 通常スレッドより優先して実行。 |
| **`Time Critical (+15)`** | **15** | 通常アプリケーションにおける最高位優先度。 |

- **Realtime 優先度 (Base Priority 16〜31)**:
  - 立体優先度ピッカーの Rank 43〜49（Realtime 優先度クラス）は、ATI を管理者権限で起動している時のみ適用可能です（通常起動時は High 優先度クラス・上限 Base 15 へ自動フォールバックされます）。

### 2.2 プロセス選択ダイアログ (Process Picker Dialog)
- メイン画面の `[Add]` から起動し、実行中のプロセス一覧から選択して `[Done]` で監視リストへ追加します（初期値は全体デフォルト設定が適用されます）。
- 先頭の赤い **`!` カラム** にチェックを入れたプロセスは `UnlistedExclusions` として登録され、リスト外（非監視）の全プロセスを一括マスクする際の対象から個別に除外されます（`!` カラムにホバー中のみ下部に説明文が表示されます）。

### 2.3 システムトレイ（タスクバー通知領域）動作
- ウィンドウ右上の「×」ボタン、または最小化でタスクバー通知領域（システムトレイ）に収納されます。
- **左クリック**: メインウィンドウを最前面に復帰表示します。
- **右クリックメニュー**:
  - **`Open Settings`**: メインウィンドウを表示します。
  - **`Start with Windows`**: Windows 起動時の自動スタートアップ常駐の有効/無効を切り替えます。
  - **`Restart`**: アプリケーションを通常再起動します。
  - **`Restart as Administrator`**: 管理者権限（UAC 昇格）で再起動します（既に管理者権限で動作中は自動非表示）。
  - **`Exit`**: アプリケーションを終了します。

### 2.4 全体設定ダイアログ (Global Settings Dialog)
メイン画面の `[Settings]` から開きます。新規登録プロセスのデフォルト値設定と、システム全体の一般プロセスに対する専用コア保護マスクを管理します。

| 項目名 | 概要・役割 | 操作仕様 |
|:---|:---|:---|
| **コア設定表** | 新規登録時に適用するデフォルトのオーディオ専用コア（行 0: `Audio Core`）および除外コア（行 1: `Excluded`）を設定（同一コアの重複防止および最低 1 コア保護が自動で動作）。 | チェックボックスで選択 |
| **`Default Audio Core (Mask)`** / **`Excluded (Mask)`** | デフォルトのオーディオ専用コアおよび除外コアをビットマスク（またはカンマ区切りコア番号）で指定。 | 直接入力または表操作 |
| **`Apply` (Audio Core 行)** | **【専用コア保護（排他チェック）】** ATI 登録プロセス（および `UnlistedExclusions`）以外の全一般プロセスに対し、「オーディオ専用コアを使わないアフィニティマスク」を一括適用し、以降の新規起動プロセスへも `INI×10` 周期で自動追従適用します。 | チェックで有効化（下段と排他連動）・OFFでポーリング停止 |
| **`Apply` (Excluded 行)** | **【除外マスク適用（排他チェック）】** ATI 登録プロセス（および `UnlistedExclusions`）以外の全一般プロセスに対し、除外コアマスクの内容を一括適用し、以降の新規起動プロセスへも `INI×10` 周期で自動追従適用します。 | チェックで有効化（上段と排他連動）・OFFでポーリング停止 |
| **`Audio Thread Priority`** | 新規登録プロセスに適用されるデフォルトの優先度。 | リストから選択 |
| **`Polling Interval (ms)`** | 監視スレッドの巡回周期（`100` / `200` / `500` / `1000` ms）。 | 数値入力（有効値へ自動補正） |
| **`Unmask All`** | 両方の `Apply` チェックが OFF かつマスク適用済みの時のみ緑（アクティブ）になり、監視中プロセスを除く全プロセスの保護マスクを明示的に一括解除して全コアの OS 標準状態へ復元します。 | クリックで解除 |
| **`OK` / `Cancel`** | 設定を保存（OK）または破棄（Cancel）して閉じます。 | クリック |

### 2.5 個別設定ダイアログ (Thread Isolation Settings Dialog)
メイン画面で対象プロセスの行をダブルクリック、または `[Edit]` ボタンで開きます。全体設定（2.4節）と同じコア設定表・マスク入力欄・スレッド優先度リストを用いて、選択中のプロセス（`Target Process`）固有の割り当てを編集し、`OK` で `ATI.ini` へ保存します（`Audio Core` にはカンマ区切り `1, 2` 等による複数コア指定も可能）。

## 3. アプリケーション種別ごとの自動判定仕様

- **Chromium 系ブラウザ (Chrome, Edge, Brave, Vivaldi 等)**:
  ブラウザ全体のプロセス群から内部の専用音声サービスプロセス（Audio Service）を自動特定し、短時間で入れ替わるスレッドの中から音声送出スレッドを追従・隔離します。
- **一般的なオーディオ・動画・通話アプリ (foobar2000, mpv, Firefox, Discord 等)**:
  スレッドの CPU 負荷動向や音声関連処理の特徴から再生・通話スレッドを特定し、音声再生が止まった無音待機状態では自動的に休眠（`sleeping...`）へ移行します。
- **独自構造アプリ (Voicemeeter 等)**:
  標準的なシグネチャを持たないアプリ向けに、スレッドの活動量と周期的な待機状態から再生スレッドを特定します。
- **Windows オーディオエンジン (`audiodg.exe`)**:
  Windows 標準のオーディオグラフ分離プロセス `audiodg.exe`（`AppType:0` 固定）では、内部スレッドが短時間で次々と入れ替わるため単一 TID の特定は行わず、**`audiodg.exe` のプロセス全体（PID）にオーディオ用コアマスク・プロセス優先度クラス・HighQoS を適用し、配下の全スレッド（全 TID）へ指定のスレッド優先度を適用**します（Col 5 表記は `PID <pid> / -`、初回 PID 確定時はスレッド数に関わらず `Chgs` を `+1`）。以降はポーリングごとに新規生成された TID を検出し次第スレッド優先度を適用して `Chgs` を `+1` 増加させます。監視リストからの削除時・Bypass 移行時・ATI 終了時には、PID を全コアおよび `Normal` 優先度クラスへ戻し、全 TID に `+2`（`Highest`）を適用して標準状態へ復元します。

## 4. 設定項目・有効値一覧 (ATI.ini)

設定は実行ファイルと同じフォルダの `ATI.ini` に保存されます。

### 4.1 全体設定セクション `[Global]`

| 設定キー名 | 設定内容・意味 | 有効値 | デフォルト値 |
|:---|:---|:---|:---|
| **`DefaultAudioCore`** | 新規プロセス登録時に初期設定される専用オーディオコア番号。 | 0 〜 (最大CPUコア数 - 1) | `5` |
| **`DefaultAudioPriority`** | 新規プロセス登録時に初期設定されるスレッド優先度。 | `-15` (Idle) 〜 `+15` (Time Critical) | `-15` |
| **`NormalCores`** | 通常スレッド群の退避先コアマスク（16進数）。 | 16進数ビットマスク (例: `0x1D`) | `0x1D` |
| **`PollingIntervalMs`** | 通常監視時の巡回間隔（ミリ秒）。 | `100`, `200`, `500`, `1000` | `500` |
| **`BoostPollingIntervalMs`** | スレッド探索・変動検知時の高速巡回間隔（ミリ秒）。 | `50`, `100`, `250` | `250` |
| **`AlwaysOnTop`** | メイン画面の最前面表示設定。 | `0` (無効), `1` (有効) | `0` |
| **`UnlistedMask`** | 未登録（Unlisted）プロセスへのアフィニティ自動退避モード。 | `0` (OFF), `1` (Audioコア除外), `2` (Excludedマスク適用) | `0` |
| **`UnlistedExclusions`** | `Select Process` 画面の先頭 `!` カラムでチェックされた、Unlisted マスク対象から除外する実行ファイル名一覧。 | カンマ区切り実行ファイル名 | 空欄 |

### 4.2 プロセス別設定セクション `[Processes]`

登録されたプロセスごとに、実行ファイル名をキーとして以下のパラメータをカンマ区切り形式で保存します。

| パラメータ名 | 設定内容・意味 | 有効値 |
|:---|:---|:---|
| **`AudioCore`** | オーディオスレッドを固定する専用コア番号。複数指定時はカンマ区切り（例: `AudioCore:11, 10`）。 | `0` 〜 (最大コア数 - 1)、複数コアカンマ区切り |
| **`AudioPriority`** | オーディオスレッドに適用する優先度。複数指定時はカンマ区切り（例: `AudioPriority:-15, -15`）。 | `-15`, `-2`, `-1`, `0`, `1`, `2`, `15`、複数カンマ区切り |
| **`NormalCores`** | 通常スレッド群を割り当てる退避コアマスク（16進数）。 | `0x` で始まる16進数マスク |
| **`Bypass`** | 一時除外状態（1: 除外中、未指定: 監視有効）。 | `1` |
| **`AppType`** | アプリ種別判定モード（0: `audiodg.exe` 専用、1: 一般オーディオ、2: Chromium、3: DAW型高負荷）。 | `0`, `1`, `2`, `3` |
| **`IgnoreSig`** | シグネチャ非依存モード。`:t` の数値指定により上位 `t` 個のオーディオスレッドを特定・隔離（デフォルト: 1）。 | `IgnoreSig`, `IgnoreSig:t` (`t` はスレッド数) |
| **`AudioPid` / `AudioTid`** | 終了時の隔離スレッド情報（次回起動時の高速復元用）。 | 数値 |

## 5. 制約事項・注意事項

1. **一時停止（`❚❚`）機能の取り扱い**:
   - 本機能は「一時的に音声を停止させ、対象スレッドが真の再生スレッドであるかを確認する」ための検証機能です。ミュート代わりに使用するとアプリ全体のデッドロックやクラッシュを引き起こす恐れがあるため、検証目的以外での使用は避けてください。
2. **一時除外（`!` / Bypass）時の挙動**:
   - チェックを入れて Bypass に移行すると、ATI による該当プロセスの監視・調整は停止します。直前までに適用されていたスレッドのアフィニティや優先度は維持され、即座に OS 標準状態に戻るわけではありません（※例外として `audiodg.exe` は、Bypass 時・監視削除時・アプリ終了時に標準状態へ自動復元されます）。
3. **多重起動防止と自己保護**:
   - 既に起動している状態で再度起動された場合、既存プロセスを終了して新しく起動します。また、ATI 自身の監視処理がオーディオ専用コアを圧迫しないよう、ATI 自身を自動的に通常コア群へ退避させて動作します。
4. **起動モード（通常起動 / 管理者権限起動）による制御範囲の違い**:
   - タスクトレイメニューの「`Restart as Administrator`」等から管理者権限で起動すると、リアルタイム優先度（Base 16〜31）が選択可能になるほか、制御できるプロセスの範囲が広がります。
   - **Unlisted マスク適用対象の拡大**: 通常起動では権限の制約によりスキップされるシステムサービスや昇格プロセスに対してもアフィニティマスクを適用できるようになります。
   - **`sleeping...` 遷移の低減**: 権限不足が原因でスレッド情報を読み取れずに `sleeping...` へ移行してしまうプロセス（`audiodg.exe` や管理者権限で動作するゲーム・アプリ等）でも、捕捉とコア隔離が可能になります。
5. **マスクを掛けられないプロセス（Windows 保護プロセス）**:
   Windows カーネルの保護機構（PPL: Protected Process Light 等）により、管理者権限であっても外部からのアフィニティ変更が拒絶される以下のシステムプロセス群は自動的にスキップされます。
   - **カーネル・仮想メモリ管理**: `System` (PID 4), `Registry`, `Secure System`, `Memory Compression`
   - **コアサブシステム**: `smss.exe`, `csrss.exe`, `wininit.exe`, `winlogon.exe`
   - **セキュリティ・認証サブシステム**: `lsass.exe`, `services.exe`, `SecurityHealthService.exe`
   - **マルウェア対策**: `MsMpEng.exe` (Microsoft Defender), `NisSrv.exe`
   - **グラフィックス・フォント・ドライバ分離ホスト**: `dwm.exe`, `fontdrvhost.exe`, `WUDFHost.exe`
   - **システム保護 `svchost.exe` 群**: セキュリティ・システムイベント等をホストする保護インスタンス群 (RPCSS, DcomLaunch, BrokerInfrastructure 等)
